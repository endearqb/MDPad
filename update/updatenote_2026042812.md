# 2026-04-28 12:xx 富文本粘贴回归 ProseMirror 原生链路

## 背景
- 用户确认不先降级 Tiptap，优先检查 schema 与粘贴链路。
- 上一轮虽然禁止了 HTML 粘贴静默降级为纯文本，但仍会出现“富文本粘贴失败，已保留剪贴板内容未插入”。
- 对比 `new_envdama_ui` 后，本轮判断关键差异是 MDPad 在 DOM paste 阶段手动 `preventDefault()` 并调用 `view.pasteHTML()`，没有完全走 ProseMirror 原生 paste 链路。

## 本轮调整
- 移除 `text/html` 粘贴的手动 `pasteHTML()` 与 sanitizer 主动接管，媒体/文件 pipeline 未处理时直接返回默认 paste。
- `handlePaste` 只记录 ProseMirror 已解析出的 slice 结构，不再二次消费剪贴板内容。
- `window.__MDPAD_LAST_PASTE_DEBUG__` 改为非侵入式诊断，记录剪贴板 types、HTML/plain text 长度、media pipeline 是否处理、ProseMirror slice 顶层节点、slice open 信息。
- 新增 paste diagnostics 测试，并增加标准 Table 与 MDPad `TableKit` 的复杂 HTML paste 对照测试。

## 验证重点
- 同一段复杂富文本粘贴后应保留标题、链接、表格、粗体、code 等结构。
- 连续粘贴两次不应出现 `Position ... outside of fragment`。
- 若仍失败，控制台查看 `window.__MDPAD_LAST_PASTE_DEBUG__`，重点看 `proseMirrorHandlePasteSeen`、`sliceTopNodeTypes`、`pipelineHandled`。
