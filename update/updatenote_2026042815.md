# 2026-04-28 15:00 Scratch 路线迁移到 Tiptap 3 官方 Markdown

## 背景

- 复杂富文本粘贴在 Tiptap 2 + `tiptap-markdown@0.8.10` + 多层 paste fallback 下仍会出现 `Position ... outside of fragment`。
- 用户选择长期成熟路线：参考 Scratch，迁移到 Tiptap 3 官方 `@tiptap/markdown` 与官方 TableKit。
- 本轮不升级 React，继续保持 React 18。

## 本次变更

- 将直接依赖的 `@tiptap/*` 包统一升级并锁定到 `3.22.4`。
- 删除 `tiptap-markdown`，新增官方 `@tiptap/markdown@3.22.4`。
- 编辑器主链路改为 Markdown-first：
  - 初始化：Markdown body 直接以 `contentType: "markdown"` 传入 Tiptap。
  - 外部同步：`setContent(bodyMarkdown, { contentType: "markdown", emitUpdate: false })`。
  - 保存同步：使用 `editor.getMarkdown()`，再拼接 front matter。
- 表格扩展改用官方 Tiptap 3 `TableKit`，停用旧 MDPad 自定义 table schema 与邻列 resize 主链路。
- 图片节点名收敛为标准 `image`，继续保留现有 React NodeView、宽度属性和图片文件粘贴到附件库的能力。
- 粘贴策略调整：
  - 有 `text/html` 的富文本完全交给 ProseMirror/Tiptap 原生 paste。
  - 仅当剪贴板没有 `text/html` 且纯文本明显是 Markdown 时，调用官方 Markdown `insertContent(..., { contentType: "markdown" })`。
  - 不恢复 sanitizer、`pasteHTML`、`pasteText` 或全局 clipboard pipeline。
- Tiptap 3 API 适配：
  - `BubbleMenu` 改从 `@tiptap/react/menus` 导入。
  - BubbleMenu 配置从 `tippyOptions` 改为 Floating UI `appendTo` + `options`。
  - `setContent` 改为 options 对象签名。
  - `TextStyle` 改为命名导入。
  - `StarterKit` 关闭内置 `link`，避免和自定义 Link 配置重复。

## 结论

- MDPad 已从 Tiptap 2 + 第三方 Markdown 插件迁移到 Tiptap 3 官方 Markdown manager。
- 混合富文本 HTML 粘贴不再被纯文本 Markdown parser 抢占，表格、标题、链接、粗体、code 等结构优先交给原生 paste。
- 官方 TableKit 替代旧自定义 table schema 后，集成测试覆盖的复杂 HTML 连续粘贴不再复现 `Position ... outside of fragment`。

## 后续建议

- 用用户真实 ProseMirror/Tiptap 来源页面做一次桌面手工粘贴验收，确认系统剪贴板 payload 与测试环境一致。
- 后续如需恢复更强的表格浮动菜单或邻列 resize，应作为 UI 层独立重建，避免再次改变 paste schema 主链路。
