# 2026-04-28 10:xx 复杂富文本粘贴链路重构

## 背景
- 对比 `new_envdama_ui` 后确认，同一段复杂富文本在参考项目中能保留标题、链接、表格/网格、行内代码等结构。
- MDPad 上一轮复杂 HTML 仍会先进入 sanitizer/fallback 准备路径，真实粘贴表现容易被压平成普通文本或低保真 Markdown。

## 本轮调整
- 富文本 HTML 粘贴改为 native HTML paste 优先：媒体/图片 pipeline 未处理后，`text/html` 会先用原始 HTML 调用 Tiptap/ProseMirror 粘贴路径。
- `prepareRichHtmlPaste` / sanitizer 仅在原始 HTML paste 抛错、返回失败或 `doc.check()` 失败时使用。
- fallback 仍保留短错误文案和纯文本降级，避免 `Position ... outside of fragment` 继续冒泡为长 toast 或启动失败。
- Markdown 保存边界改为保真优先：简单表格继续导出为 GFM table；合并单元格、嵌套表格等 Markdown 无法无损表达的复杂表格保留 raw HTML block。

## 验证重点
- 同一段复杂富文本连续粘贴两次，不应报 `Position ... outside of fragment`。
- 表格、标题、链接、粗体、行内 code 不应在第一入口被 sanitizer 压平。
- 保存 Markdown 时不再强行把复杂表格转换成 GFM 表格，避免 reopen 后结构丢失。
