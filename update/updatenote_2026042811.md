# 2026-04-28 11:xx 复杂富文本粘贴纯文本退化修复

## 背景
- 用户对比 `new_envdama_ui` 后确认，同一段复杂富文本在 MDPad 中仍会退化成单个巨大纯文本段落。
- 这说明实际链路仍可能进入 `text/plain` 或 plain-text fallback，而不是保留 HTML 富文本结构。

## 本轮调整
- 在真实 paste 入口增加 `window.__MDPAD_LAST_PASTE_DEBUG__`，记录剪贴板 types、HTML/plain text 长度、native paste、sanitizer 和 fallback 的路径状态。
- `text/html` 存在时，native HTML paste 仍为第一入口；若 native 和结构化 sanitizer 都失败，不再静默插入 `text/plain` 大段落。
- Markdown 图片文本 paste handler 在剪贴板已有 `text/html` 时不再抢先处理，避免富文本内容被纯文本路径接管。
- 对齐 `new_envdama_ui` 的非 Pro 基础能力，新增 `Underline`、`TextStyle`、`Color`、`TextAlign` 扩展，帮助 HTML paste 保留 underline、颜色和对齐信息。

## 验证重点
- 复杂富文本粘贴后不应成为一个巨大 paragraph。
- 若仍失败，可在控制台查看 `window.__MDPAD_LAST_PASTE_DEBUG__` 判断失败阶段。
- 连续粘贴两次不应出现 `Position ... outside of fragment`。
